🔍 El Desafío Actual (la motivación del proyecto)

En la sociedad actual, acceder a información cívica verificada, comprensible y atractiva es a menudo un desafío.

La información está dispersa, es técnica o difícil de encontrar, generando una brecha de conocimiento que dificulta la participación ciudadana informada.

¿Cómo podemos hacer que el aprendizaje sobre normativas, derechos y deberes sea accesible y motivador para todos?

🎯 Objetivos del proyecto

  • Empoderar a la ciudadanía con conocimiento
  • Transformar contenido especializado en aprendizaje activo
  • Fomentar comunidad y participación
  • Abrir espacio a productores y consumidores de saber

Nuestra solución: Ciudadano Consciente

Una plataforma web interactiva que conecta a ciudadanos con información verificada y expertos.

Transformamos el aprendizaje cívico en una experiencia lúdica y enriquecedora, similar a un juego.

Fomentamos una comunidad informada, conectada y participativa.

¿Cómo funciona?

1. Instituciones aportan

Organismos (tránsito, justicia, parques, etc.) comparten datos y conocimiento verificado.

2. Caminos de aprendizaje

Se crean "Paths" temáticos con niveles y actividades interactivas (quizzes, etc.).

3. Ciudadanos aprenden

Los usuarios exploran los paths, responden actividades, ganan conocimiento y miden su progreso.

¡La comunidad participa! (Pool de preguntas)

Los usuarios proponen temas de interés, votan preguntas y guían la creación de nuevo contenido (Community Driven).

¿Para quién es?

Ciudadanos

Estudiantes, conductores, opositores, guías, cualquier persona con ganas de aprender sobre su entorno cívico.

Instituciones Productoras

Gobiernos, ONGs, Parques Nacionales, Poder Judicial, Bomberos, etc., que desean difundir conocimiento.

Desarrolladores (Futuro)

Comunidad que puede proponer nuevos tipos de actividades interactivas (templates).

Metodología de Desarrollo

Adaptación de metodologías ágiles: Scrum y Kanban.

  • Enfoque en iteraciones basadas en eventos (Kanban).
  • Uso de historias de usuario y estimaciones (Scrum).
  • Tablero Kanban visual (Google Sheets) para seguimiento.
  • Limitación del WIP para mantener el foco.
  • Revisión continua de prioridades.

🛠️ Realización del proyecto

2.1. Diseño de arquitectura (API y Web App)

De acuerdo a los requerimientos, elegimos implementar una API Rest (pedirle cosas al servidor de una forma específica) y una WebApp (una aplicación que se puede ejecutar en navegadores web).

Esto involucra generalmente contar con una base de datos y alguna manera de gestión de usuarios.

🛠️ Realización del proyecto

2.2. Diseño de arquitectura (modelo de datos)

El modelo de datos surgió del análisis inicial de requerimientos y se terminó de definir a medida que el sistema fue desarrollándose.

Al modelo de datos propio de la problemática (usuario, organización, nivel, etc.) hubo que rodearlo de entidades nomencladoras y agrupadoras como votos, etiquetas, vistas de la base de datos, etc.

🛠️ Realización del proyecto

3. Desarrollo web clásico: backend y frontend

Al momento de iniciar el proyecto ambos estudiantes se encontaban trabajando en el área de desarrollo de la Municipalidad de Ushuaia, uno en el front end (lo que vé el usuario) y otro en el backend (lo que pasa debajo del capot).

Debido a esta coyuntura, optamos por materializar el proyecto de igual manera.

Pero ¡ojo!, pronto surgió la necesidad de abordar integralmente y en conjunto una característica fundamental del sistema: el manejo de usuarios.

🛠️ Realización del proyecto

4. Integración con Keycloak

Conocíamos las funcionalidades que ofrecía la herramienta. Sabíamos que nos serviría para autenticar (identificar usuarios) y autorizar (quién accede a qué) pero nunca lo habíamos puesto en marcha por nuestra cuenta. Esta fué una de las principales demoras del proyecto.

Una vez que logramos poner en marcha la integración con la solución (levantar un servidor de la solución, una base de datos dedicada y conectar el backend y el front end) y las configuraciones particulares que pretendíamos, todo fluyó en el ambiente local.

  • Creamos reinos, clientes y roles
  • Añadimos atributos a los usuarios
  • Mapeamos atributos del usuario al token
  • Generamos una nueva API que nos permite conectarnos programáticamente con el servidor

Hasta que... surgió la necesidad de replicar lo local en un ambiente productivo (no era explícitamente necesario pero ya que estamos, implementemos un producto real 😅). Y ahora fuimos capaces de:

  • Loguear usuarios a través de Google, LinkedIn y Github
  • Enviar correos a través de la plataforma para verificaciones

🛠️ Realización del proyecto

5. Despliegue en Servidor

Para que los usuarios puedan acceder a la WebApp fue necesario accesibilizarla a través de una url. Esto demandó contratar un nombre de dominio (lo que se escribe en el navegador) y un servicio de hosting (donde se alojan los datos y en este caso, el sistema entero). Con esto, ya tenemos nuestra aplicación en su sitio web.

🏗️ Arquitectura y Tecnología

Sistema basado en microservicios y desplegado en contenedores para escalabilidad y mantenibilidad.

  • Frontend: React + Vite (Diseño Mobile-First)
  • Backend APIs: Java + Quarkus
  • Base de datos: PostgreSQL
  • Autenticación: Keycloak
  • Despliegue: Docker + Nginx

🏗️ Arquitectura y Tecnología

Backend - Servidor Keycloak

    Servidor Keycloak utilizado como servidor de autenticación.

  • Las aplicaciones "cliente" se registran y solicitan a Keycloak que se encargue de darle credenciales válidas a los usuarios.
  • Una vez que el usuario se loguea en la aplicación cliente con las credenciales proveídas por Keycloak, el cliente verifica que las credenciales hayan sido firmadas con su clave pública (si reconoce las credenciales como válidas para sí mismo).
  • Desplegado en contenedor de Docker

Diagrama de Servidor Keycloak.

🏗️ Arquitectura y Tecnología

Backend - API Rest Keycloak como proxy

    API Rest desarrollada utilizando la librería de Java de Keycloak. Agregando un nuevo nivel de indirección adicional (proxy), el servidor de autenticación es utilzado por la API Ciudadano Consciente a través de esta API auxiliar.

  • Se encarga de recibir las peticiones de la API Ciudadano Consciente y recuperar datos o performar alguna acción en el servidor Keycloak (por debajo hace peticiones HTTP).
  • Programado en Java utilizando el framework Quarkus
  • Desplegado en contenedor de Docker

Diagrama de API Rest Keycloak como proxy.

🏗️ Arquitectura y Tecnología

Backend - Unidades de persistencia

  • Dos bases de datos: una para el servidor de autenticación Keycloak y otra para la API Ciudadano Consciente. Ambas son bases de datos relacionales Postgresql
    • Se encargan de la persistencia y disponibilidad de los datos necesarios.
    • Desplegadas cada una en su propio contenedor de Docker
  • Sistema de archivos del servidor utilizado para almacenar las imágenes

Diagrama de las unidades de persistencia.

🏗️ Arquitectura y Tecnología

Servidor Web - Nginx

Nginx se encuentra instalado en el servidor remoto donde se aloja el front end y los contenedores del backend.

Es el encargado de manejar las peticiones que llegan a la IP pública asociada al dominio y forwardearlas a los servicios apropiados.

Es decir, recibe una petición y sabe a cuál de los servicios pasarsela (puede filtrar, modificar, balancear, etc.).
