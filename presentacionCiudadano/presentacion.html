El desafío actual (la motivación del proyecto)

En la sociedad actual, acceder a información cívica verificada, comprensible y atractiva es a menudo un desafío.

La información está dispersa, es muy técnica o difícil de encontrar, generando una brecha de conocimiento que dificulta la participación ciudadana informada.

¿Cómo podemos hacer que el aprendizaje sobre normativas, derechos y deberes sea accesible y motivador para todos?

🧪 Nuestra solución: Ciudadano Consciente

Una plataforma web interactiva que conecta a ciudadanos con información verificada y expertos.

Transformamos el aprendizaje cívico en una experiencia lúdica y enriquecedora.

Fomentamos una comunidad informada, conectada y participativa.

Objetivos del proyecto

  • Empoderar a la ciudadanía con conocimiento
  • Transformar contenido especializado en aprendizaje activo
  • Fomentar comunidad y participación
  • Abrir espacio a productores y consumidores de saber

¿Cómo funciona?

1. Instituciones aportan

Organismos (tránsito, justicia, parques, etc.) comparten datos y conocimiento verificado.

2. Caminos de aprendizaje

Se crean "Paths" temáticos con niveles y actividades interactivas (quizzes, etc.).

3. Ciudadanos aprenden

Los usuarios exploran los paths, responden actividades, ganan conocimiento y miden su progreso.

¡La comunidad participa! (Pool de preguntas)

Los usuarios proponen temas de interés, votan preguntas y guían la creación de nuevo contenido (Community Driven).

Realización del proyecto

2.1. Diseño de arquitectura — API Rest y WebApp

En base a los requerimientos funcionales, optamos por una arquitectura cliente-servidor que separa el acceso a los datos y la gestión de operaciones complejas a través de la API Rest, facilitando que la WebApp consuma información y funcionalidades sin tener que resolver directamente la lógica de acceso o integración de múltiples fuentes.

La API Rest permite la gestión estructurada de datos y funcionalidades mediante solicitudes HTTP, mientras que la WebApp ofrece una experiencia interactiva desde el navegador y sirve de interfaz para la configuración de los datos necesarios para el funcionamiento del sistema.

Esta arquitectura incluye una base de datos relacional y un sistema de autenticación de usuarios para proteger los recursos.

Realización del proyecto

2.2. Diseño del modelo de datos

El modelo de datos fue definido inicialmente a partir del análisis de requerimientos y evolucionó conforme el desarrollo avanzaba.

Las entidades centrales —como Usuario, Organización y Nivel— se complementaron con entidades auxiliares que permiten estructurar, etiquetar y registrar interacciones: votos, etiquetas, vistas, entre otros.

Realización del proyecto

3. Desarrollo web clásico: Backend y Frontend

Ambos integrantes del equipo se desempeñaban profesionalmente en el área de sistemas de la Municipalidad de Ushuaia: uno en el desarrollo frontend y otro en el backend.

Esta experiencia influyó en la decisión de dividir el trabajo de forma tradicional: frontend (interfaz de usuario) y backend (lógica y base de datos).

Sin embargo, uno de los principales desafíos fue implementar de forma colaborativa y coordinada una funcionalidad crítica del sistema: la gestión de usuarios y autenticación.

Realización del proyecto

4. Integración con Keycloak

Ya conocíamos las capacidades de Keycloak como solución para autenticación (identificación de usuarios) y autorización (control de acceso), pero era nuestra primera vez configurándolo de forma independiente. Esta etapa representó una de las principales demoras del proyecto.

Tras desplegar un servidor de Keycloak con su base de datos dedicada, logramos integrarlo exitosamente con nuestro backend y frontend, incluyendo las configuraciones que requería el sistema.

  • Creación de reinos, clientes y roles personalizados
  • Asignación y mapeo de atributos al token del usuario
  • Desarrollo de una API personalizada para interacción programática

Posteriormente decidimos avanzar más allá del entorno local y replicar la configuración en un entorno productivo. Esto nos permitió implementar funcionalidades avanzadas como:

  • Inicio de sesión mediante Google, LinkedIn y GitHub (OAuth2)
  • Envío de correos automáticos para verificación de identidad

Realización del proyecto

5. Despliegue en servidor con IP pública

Para que la WebApp fuera accesible al público, fue necesario desplegarla en un servidor con un nombre de dominio y un servidor virtual privado con IP pública.

Adquirimos un dominio personalizado, configuramos los DNS y montamos el sistema completo (backend, frontend y Keycloak) en un entorno productivo que hoy funciona como el sitio web oficial del proyecto.

El costo del dominio por un año fué de AR$ 1.844 y el costo del servidor privado por una año fué de AR$ 131.388. El servidor cuenta con dos núcleos, 8GB de RAM y 100 GB de almacenamiento. (Existen alternativas más económicas e incluso gratuitas para ambas soluciones)

Arquitectura y tecnología

Sistema basado en microservicios y desplegado en contenedores para escalabilidad y mantenibilidad.

Stack tecnológico:

  • Frontend: React + Vite (Mobile-First)
  • Backend APIs: Java + Quarkus
  • Base de datos: PostgreSQL
  • Autenticación: Keycloak
  • Despliegue: Docker + Nginx

Diagrama simplificado del stack.

Componentes del sistema

  • WebApp: Ciudadano Consciente
  • API: API Rest Ciudadano Consciente (Java + Docker)
  • Auth Server: Keycloak (Java + Docker)
  • API Proxy: API Rest Keycloak (Java + Docker)
  • DB: PostgreSQL Ciudadano Consciente (Docker)
  • DB: PostgreSQL Keycloak (Docker)
  • Web Server: Nginx

Diagrama simplificado de la arquitectura.

Frontend

  • React JS: El frontend está desarrollado utilizando React JS y construido como una SPA (Single Page Application), una aplicación de página única donde la navegación y actualización de contenido se realiza dinámicamente sin recargar toda la página.
  • Vite: Se emplea Vite como bundler y herramienta principal de desarrollo, lo que agiliza la compilación y el flujo de trabajo.
  • Mobile-First: El diseño e implementación siguen la filosofía Mobile-First, priorizando la experiencia en dispositivos móviles desde el inicio.

Diagrama del frontend.

Backend - API Ciudadano Consciente

API Rest desarrollada en capas para modularidad y responsabilidades únicas.

  • Interfaz entre el front y las acciones o datos del sistema.
  • Programada en Java con Quarkus.
  • Desplegada con Docker.

Diagrama de arquitectura de capas del backend.

Autenticación - Keycloak

Servidor Keycloak utilizado como proveedor de identidad.

  • Emite credenciales firmadas para usuarios autenticados.
  • Validación de tokens por parte del frontend y backend.
  • Desplegado en contenedor Docker.

Diagrama del servidor de autenticación.

API Proxy - Keycloak

API intermedia entre la API principal y el servidor de autenticación.

  • Encapsula la lógica de interacción con Keycloak.
  • Implementada con la librería de Java para Keycloak.
  • Permite desacoplar Keycloak del resto del sistema.
  • Desplegada en Docker.

Diagrama del proxy API Keycloak.

Persistencia de datos

  • Dos bases de datos PostgreSQL: una para Keycloak y otra para Ciudadano Consciente.
  • Ambas desplegadas en contenedores Docker.
  • Sistema de archivos del servidor utilizado para almacenar imágenes.

Diagrama de unidades de persistencia.

Servidor web - Nginx

Nginx gestiona las peticiones a la IP pública asociada al dominio.

  • Encargado de redirigir tráfico a los servicios correctos.
  • Puede realizar filtrado, modificación o balanceo de carga.
  • Desplegado en el mismo servidor que el frontend y contenedores.

Diagrama del servidor web Nginx.

Conclusiones del equipo

Errores

  • Subestimar complejidad de Keycloak: conocíamos la utilidad de la herramienta pero desconocíamos su configuración para hacerla funcionar como queríamos.
  • Tiempo en características no esenciales: empleamos mucho tiempo en integraciones espectaculares que no usamos o no terminamos de implementar para esta entrega (cliente Rest de Github, entidades de templates funcionales, etc.).

Conclusiones del equipo

Aprendizajes

  • Utilizar herramientas de gestión integradas (Github Projects e Issues, Wakatime, etc.).
  • Escuchar a los docentes cuando recomiendan conseguir un cliente que nos demande características y plazos de entrega.
  • Finalizar el proyecto antes de perder la motivación (😅) o terminarlo igual. ¡No abandonar!

Conclusión del proyecto

Buscamos construir una sociedad más informada, crítica y participativa a través del conocimiento accesible y la tecnología.
